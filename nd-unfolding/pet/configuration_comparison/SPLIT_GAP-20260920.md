# The stage splits are frozen but not implemented. This blocks a valid final result.

**CITABLE FOR:** the gap, its consequence, and what closing it requires.
**NOT CITABLE FOR:** any claim that the campaign as queued satisfies the design.

## What is frozen

`frozen_design.SPLITS` assigns every event to `tuning` (0.20), `pilot` (0.20)
or `final` (0.60), "by a hash of the event identity (source, run, subrun, gate,
occurrence), so the same event lands in the same split for BOTH arms and across
reruns", with `tuning ∩ pilot = tuning ∩ final = pilot ∩ final = empty`.

## What the driver does

Nothing. `run_arm_evaluation` never reads `SPLITS`. It calls the production
loader with `max_events=2,000,000` and the production subsample seed, so the
MC leg is `sort(default_rng(0).choice(N, 2_000_000))` — **the same 2,000,000
events for every stage**.

## Why it matters

Tuning selects the learning rate. The pilot sizes the final. If all three read
the same events, the learning rate is chosen on the data the effect is then
measured on, and the pilot's variance estimate is an in-sample one. The
interval would be narrower than the truth by an amount nobody can quantify
after the fact. This is directive item 14, and it is not a detail — it is the
difference between a comparison and a fit.

## Why it was not patched here

The loader takes `max_events` and `seed`; it does not take a row selection, and
it is production code that this lane must not alter. The three available routes
each carry a real risk:

1. **Stage-specific subsample seeds.** Cheapest, and *wrong*: three independent
   draws of 2M from 49M overlap by about 4% in expectation. Approximately
   disjoint is not disjoint, and the overlap would be undocumented.
2. **Post-loader row selection on the MC leg.** Feasible — the substitution
   already rewrites loader arrays in place — but the loader computes weight
   normalisations over the rows it drew, and subsetting afterwards silently
   invalidates them. Correct only with the normalisation recomputed and
   checked, which is the part that needs care.
3. **A row selection argument on the loader.** Cleanest and smallest, but it
   edits production.

Route 2 is the one to take, with route 3 proposed to the production owner
separately. Guessing at it at the end of a long session, against a queued
campaign, is how a subtler defect than the five already found today gets in.

## The continuation

1. Implement `split_of_event(identity) -> {tuning, pilot, final}` from
   `SPLITS["split_seed"] = 20260920` over `(source, run, subrun, gate,
   occurrence)`; the identity arrays and the `occurrence` discriminator are
   already in the sidecar.
2. Select the stage's MC rows after `build_fullevent_loaders`, recompute the
   weight normalisation the loader applied, and assert the three stages'
   index sets are pairwise disjoint and identical across arms and reruns.
3. Re-cost: the final stage sees 0.60 of the events, not all of them, so the
   366 GPU-hour projection moves and must be re-derived before launch.
4. Re-run `sbatch_campaign_smoke.sh` before submitting.

**Until this lands, a completed campaign would produce a number, and the number
would not mean what the design says it means.**

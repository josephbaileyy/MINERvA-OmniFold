## 2. The code change (shared source NOT modified)

`MINERvA101/MINERvA-101-Cross-Section/runEventLoopOmniFold.cpp` is byte-pinned by
`nd-unfolding/pet/sbatch_p3f_pet_fullevent_evloop_array.sh`. The hash-binding gate refused an in-place edit, so
the tracked source stays unchanged (sha256 `57792e42…`). W2's change is applied only to a private copy:

- **`publication/w2/src/event/RecoilResponseUniverse.h`** subclasses `CVUniverse`.
  - Reco `NewEavail()` is multiplied by `s = 1 + nsigma·δ`.
  - The reco energy transfer `q0 = <tree>_recoil_E` is multiplied by `s` inside `RecoQ3()` and `RecoW()`, whose
    formulas are repeated verbatim from `CVUniverse`.
  - `IsVerticalOnly() = false`.
  - Truth getters, weights and cuts are inherited unchanged. No selection cut reads the recoil: the cuts are
    ZRange, Apothem, MaxMuonAngle, HasMINOSMatch, NoDeadtime and IsNeutrino (`runEventLoopOmniFold.cpp:1710–1715`).
  - The data tree uses `dataCV`, so data is never shifted. Signal and background reco use the active universe, so
    they shift coherently.
- **`publication/w2/src/runEventLoopOmniFold-recoil-response.patch`** (87 lines) adds three things:
  - a strict parser for `MNV101_RECOIL_RESPONSE_DELTA`, accepting a finite value in [0, 1);
  - the band `RecoilResponse = {s = 1−δ, s = 1+δ}`, in both the reco and the truth maps, **only when the variable is
    set**;
  - a refusal when the variable is combined with `MNV101_SKIP_SYST`.

  The per-universe branch loops run only under `MNV101_DUMP_UNIVERSES`, which the active runs leave unset, so the
  band changes nothing else.
- **`publication/w2/build_w2.sh`** copies the canonical source tree twice into the namespace.
  - It first refuses unless the four tracked files equal this commit's copies.
  - It builds `base` (unmodified) and `mod` (header plus patch) against the installed MAT libraries.
  - The source trees differ only by the header and the patch (`diff -r`).

| check | comparison | verdict |
|---|---|---|

**What each ±4% PASS establishes:**
- **E_avail:** in every passing row (85,166 signal, 2,616 background), reco E_avail equals s × base, with the
  largest relative deviation ≤ 2.3e-16.
- **q0:** the reco q0 is recovered as √(q3² + W²) − M. It equals s × base within 3e-14 GeV on 83,873 (−4%) and 83,911
  (+4%) signal rows, and on 2,528 (−4%) and 2,530 (+4%) background rows. The rest (1,255–1,293 signal, 86–88 background, ≈ 1.5%) are rows the producer
  clipped to W = 0 because W² < 0. The identity does not hold there, so those rows are excluded and counted.
- **Everything else is identical:** pass flags, every truth and weight branch, muon p_T and p∥, and the whole data
  tree.

**A checker defect, found and fixed.** The first run of the comparer flagged exactly those W = 0 rows. All
unclipped rows passed, so the identity assumption was the fault, not the universe (`a661bd75`).

**Byte identity.** The ROOT files differ byte for byte only through ROOT metadata (timestamps and UUIDs); see
`checks/smoke-omnifiles.sha256`. Equality is established on content.

**Full 1A** (the costing outputs `cost1A/evloop/mod_rr0.root` and `mod_rr1.root`; `checks/full1A_rr1_vs_rr0.json`).
The two shifted files were compared with each other at scale 1.04/0.96: **PASS**.
- Rows: 1,736,833 passing signal and 52,626 background.
- E_avail: relative deviation ≤ 4.4e-16.
- q0: matches within 6e-14 GeV on 1,710,436 signal and 50,913 background rows. 26,397 signal and 1,713

No full-1A *unshifted* base run was made, to save budget. So the no-op property is shown on the smoke subset,

## 5. Cost gate

**W2a + W2b = 0.10 + 2.38–3.03 = 2.5–3.1 CPU node-h without margin, and ≤ 6.2 with one full retry of every
step. Both are within the 8.0 ceiling. Cost gate: GO.**

W2b still needs the **other two gates**, and neither is met yet:
1. the independent review clears the implementation;
2. D2 has landed: the lost-seed recovery resolution and its recompute cross-check.

A failed gate, a control FAIL, or an overrun past 8.0 stops W2. Each W2b job is sized so that a job hitting its
time limit cannot breach the ceiling.

## Detail

`AGENTS.md`, `docs/ESTIMATOR_REGISTRY.md`, `docs/HIGHER_DIM_OMNIFOLD_DESIGN.md`, `docs/analysis-note/sec_3d.tex` (*"numerical rank $247$ (of 1431)"*, a quote that **spans a newline** and is invisible to a line-oriented grep) and 13 others state **rank 247** with no `rcond`/tolerance. The standing rule — *never quote a bare rank; state the cutoff with every rank* — is `VL143` item (3) and is restated in `OUTCOME-20260922-3d-covariance-…`. A rank is a **step function of its cutoff**: on the sibling `(E_avail,W)` object the retained count moves **2 → 42** across the cutoffs `VL145` scans, so a bare `247` is not a measurement. ⚠ **THIS ROW'S ORIGINAL PREMISE WAS FALSE AND THE NINTH INDEPENDENT REVIEW REFUTED IT WITH ONE `grep`.** It read *"the cutoff that produced `247` is not recorded in any receipt I could find"*. **It is recorded, in the producing script the ledger names.** `3d-unfolding/genie/compare_3d_fullcov.py` computes `hard_rank = int((evals > 1e-12 * lmax).sum())` and prints `hard rank (>1e-12) = {hard_rank}/{n_rep}`, and `VALIDATION_LEDGER.md` attributes `247` to that script using its own label word (*"hard rank `247/1431`"*). **So the ledger's own `hard rank 247/1431` is `247 of 1431 at rc = 1e-12`** — the same cutoff as the new 3D object's `263`. ⚠ **Scoped deliberately:** that is established for the ledger line, which names the script and uses its label word. It is **not** a blanket attribution for every `247` in the tree, some of which are declared at `1e-10`; an earlier revision of this row asserted it as one. I declined an available repair on a premise one command refutes, which is this row's own subject class. **WHAT REMAINS GENUINELY OPEN:** the 17 bare sites still omit the cutoff; and three sites pair `247` with the `1e-10` cutoff — ⚠ this read *"with a **different** number"*, but the first of them states the count is 247 at BOTH cutoffs, which answers the question this row leaves open below — `3d-unfolding/genie/README.md` (*"hard rank 247; tol=1e-10 keeps exactly the non-null modes"*), `docs/COLLABORATOR_QUESTIONS.md` itself (item 2 declares `λ > 1e-10 λ_max`, item 3 carries it onto the 3D `rank 247`), and `REQUIREMENTS-20260814-cstat-assembly-conventions.md` quoting it. ⚠ **AND THIS ROW PUT `COLLABORATOR_QUESTIONS.md` IN BOTH OF ITS MUTUALLY EXCLUSIVE CATEGORIES** — listed among the bare-rank sites AND cited as the source of a cutoff pairing, in the same cell. It is a cutoff-bearing site; it is removed from the bare list, which is why the headline says *"most… omit the cutoff"* and no longer *"no cutoff anywhere"*. `--tol` defaults to `1e-10` and is the **pseudo-inverse** tolerance, a different quantity from `hard_rank`'s hardcoded `1e-12`. Whether the two cutoffs yield the same count holds iff the spectrum has no eigenvalue in `(1e-12·λ_max, 1e-10·λ_max]`. ⚠ **I marked this UNVERIFIED on the ground that measuring it *"needs the 3D covariance product and ROOT"*; that was too strong.** The same script prints it: `compare_3d_fullcov.py` sets `tol_sweep = [1e-6, 1e-8, 1e-10, 1e-12]` and prints `ndf = keep.sum()` per tol in the same run, and `3d-unfolding/genie/README.md` records that run's output. So a RECORD of the `1e-10` count exists and I declined to read it while accepting a ledger line from the same script for `1e-12`. **What is genuinely unverified is only a fresh re-measurement** (that does need the product and ROOT); the recorded values should be read first. Do not "fix" those two sites to `1e-12` without measuring first. None of the 17 bare sites was introduced in `177af61b..3b60abb0`. **CHECK:** before quoting `247` anywhere new, find or re-measure its cutoff; the new 3D projection's own retained count is **263 of 1431 at `rc = 1e-12`** and is a different object.

\section{Codebase layout and terminology}
\label{app:codebase}

The analysis chain has four components; the note refers to them by the names in italics below.

\begin{itemize}[itemsep=2pt]
  \item \emph{Event loop} (C++): \texttt{runEventLoopOmniFold}, built on the
        MINERvA Analysis Toolkit (MAT) and the MINERvA-101 framework. It
        reads production AnaTuples, applies selection and systematic-universe
        machinery, and writes per-event ROOT trees.
  \item \emph{Event-loop outputs} (\emph{omnifiles} in the code): per-event
        records for data, for simulated signal with paired true and
        reconstructed quantities, for simulated background, and for the
        truth-level efficiency denominator, together with the exposure in
        protons on target (POT). The \texttt{\_universes\_full} variants add
        per-universe weight and shifted-kinematics branches.
  \item \emph{Driver} (Python): per-analysis orchestration in
        \texttt{2d-unfolding/unfold\_2d\_omnifold\_unbinned.py} and its
        $N$-dimensional generalization
        \texttt{nd-unfolding/unfold\_nd\_omnifold\_unbinned.py}. The driver
        builds training arrays from the event-loop outputs, applies
        purity-weight background subtraction (\S\ref{sec:method-algo}),
        runs the engine, and extracts the cross section.
  \item \emph{Engine} (Python):
        \texttt{unbinned\_unfolding/python/omnifold.py} implements the
        OmniFold iteration independently of the learner backend: LightGBM for
        the central value and the uncertainty ensembles, scikit-learn's
        exact-split gradient boosting (\texttt{exact}) for the cross-check,
        its histogram gradient boosting (\texttt{hist}) as an alternate, and a multilayer perceptron (MLP)
        for a further cross-check.
\end{itemize}

Point-cloud (PET) code under \texttt{nd-unfolding/pet/} supports future work
(App.~\ref{sec:pet}) and produces no result in this note.

Scripts, figure files and stored outputs call \emph{training-seed variation}
\texttt{seedscan}; the two names denote the same variance source. The quoted
training-seed block is assembled by the aggregation step of the 2D
production (Ref.~\cite{NoteRecords2026}, \texttt{variance-sources}), not by the \texttt{seedscan} scripts.

\section{Codebase layout and terminology}
\label{app:codebase}

The analysis chain has four components; the note refers to them by the names in italics below.

\begin{itemize}[itemsep=2pt]
  \item \emph{Event loop} (C++): \texttt{runEventLoopOmniFold}, built on the MINERvA Analysis Toolkit (MAT) and the MINERvA-101 framework. It reads production AnaTuples, applies selection and systematic-universe machinery, and writes per-event ROOT trees.
  \item \emph{Event-loop outputs} (\emph{omnifiles} in the code): per-event records for data, for simulated signal with paired true and reconstructed quantities, for simulated background, and for the truth-level efficiency denominator, together with the exposure in protons on target (POT). The \texttt{\_universes\_full} variants add per-universe weight and shifted-kinematics branches.
  \item \emph{Driver} (Python): per-analysis orchestration, by a two-dimensional driver and its $N$-dimensional generalization. The driver builds training arrays from the event-loop outputs, subtracts the background by the method an option selects, the purity weight by default (\S\ref{sec:method-algo}), or negative-weight injection with or without the Stay-Positive refinement (App.~\ref{app:negweight}), runs the engine, and extracts the cross section.
        % Accuracy fix (unscored; director ruling 2026-10-26): the option is --bkg-mode {purity, negweight,
        % negweight-refined}, default purity (2d-unfolding/unfold_2d_omnifold_unbinned.py:1362-1377 and :1825-1870 @ ddf16f10; nd-unfolding/unfold_nd_omnifold_unbinned.py:619-630 and :900-1030 @ ddf16f10);
        % the 2D result uses the refined negative-weight mode (sec:negweight-footing).
  \item \emph{Engine} (Python, \texttt{unbinned\_unfolding/python/omnifold.py}): the OmniFold iteration, implemented independently of the learner backend: LightGBM for the central value and the uncertainty ensembles, scikit-learn's exact-split gradient boosting (\texttt{exact}) for the cross-check, its histogram gradient boosting (\texttt{hist}) as an alternate, and a multilayer perceptron (MLP) for a further cross-check.
\end{itemize}

Point-cloud (PET) code is under \texttt{nd-unfolding/pet/} (App.~\ref{sec:pet}).

The quoted training-seed block is assembled by the aggregation step of the 2D production, not by the scripts that run the training-seed variation.

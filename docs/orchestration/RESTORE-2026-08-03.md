**How to tell it actually did something — this step's exit status will not tell you.**
`backfill_completion_markers.sh` exits **0** on a pattern that matches nothing, printing
only `[backfill] no files matched: <pattern>`. That is deliberate (a sweep over many
patterns must not abort under `set -e`) and it means a wrong cwd, a purged directory and a
genuinely-already-complete family are **indistinguishable by exit code**. The check is the
summary line, on every invocation:

```
[backfill]   <N> already marked, <M> would be marked, <F> FAILED validation
```

`N = M = F = 0` together with `no files matched` means you are in the wrong place or the
data is gone — go find out which before moving on. It does not mean the family was clean.

**Read the FAIL list, do not just note the count.** Anything that fails validation is left
unmarked and will be regenerated. Under the old size-only guard every one of those would
have been skipped as done — that list *is* the population of hidden partials, and it is
the first time this repo has been able to enumerate it. Record it.

Two things to refuse:

- **Do not use `--validator size`.** It stamps on a bare nonempty check, which is the
  BEN-023 defect performing itself. It exists only for artifact families with no
  structural check and warns on every use.
- **Do not set `RESUME_ADOPT_LEGACY=1` to make a launcher quiet.** Same objection, and it
  prints a warning per unit precisely so it cannot become the default.

The npz validator decompresses every member, so a truncated npz fails there rather than
three stages downstream. Budget I/O time on the large families accordingly.

acceptance effect — the gain is still +0.82. The likely outcome is a comfortable pass with ~3× of
margin, and the point of measuring is to say so with a number instead of an assumption.

**Do not use `leak = corr²` to shortcut this.** That relation held to 0.004 over corr ≤ 0.62 and

adds nonlinear structure a classifier exploits. It is a *lower bound* on the leak, so it errs by
**overstating** the extension's value — fine as a weak-coupling sanity check, wrong as a
substitute for reading the measured curve in
`$MNV_REPO/nd-unfolding/products/pet/coupled_phi_curve.json` (present and verified

azimuthal mismatch at all. Recovering the tilt through a pT proxy is also not the same as seeing
φ — at corr 0.62 the baseline "recovers" 0.389 of the tilt for the wrong reason, and would keep
doing so when the true correlation shifted.

# Interactive agent notifications

Cluster Codex and Claude sessions notify the existing MINERvA email + ntfy
fanout when a turn completes and waits for input. Claude also notifies on
permission/elicitation prompts, turn failures, and session termination.

The account-level installation is generated by:

```bash
cd /pscratch/sd/j/josephrb/MINERvA-OmniFold/docs/orchestration
/usr/bin/python3.11 install_agent_notifications.py
```

It installs `~/bin/minerva-agent-notify`, adds the user-level Codex `notify`
command to `codex-homes/{personal,school,school2}/config.toml`, and merges
Claude hooks into `claude-homes/{personal,school}/.claude/settings.json`.
Existing settings and hooks are preserved; rerunning the installer is
idempotent.

Hook delivery is detached and fail-open. Mode-0600 envelopes live briefly in
`state/waker/agent-notify-spool/`; the delivery log is
`state/waker/logs/agent-notifications.log`. Email contains the session name
and available event detail. ntfy retains the generic body configured in
`notification-config.json`, while its title names the tmux session and action.
Concurrent hooks for the same session and attention state are collapsed within
a 30-second window.

Run a live fanout test with:

```bash
~/bin/minerva-agent-notify test
```

Codex reads `notify` at process startup, so restart/resume an already-running
Codex CLI once to activate the hook. Claude settings are account-level; use
`/hooks` to inspect registration in a running session if needed.

### 2.1 A refutation cannot outrun what it refutes — corroboration, and it yields STAMP scope

`CRITERIA §4.2:473-475` is the only remedy the governing criteria ever proposed for X:

> *"The cheap fix is a receipt, not a re-run — dump the existing `TParameter`s and slab seed stamps

`SCOREBOARD §1` reports that exactly this dump was performed — `receipt_candidate_stamps_5d.json`,
both July products run as named negative controls — and every named stamp came back `ABSENT`, 4 keys
against the candidate's 13. **The claim's whole content is that §4.2's remedy fails on X and cannot be
repaired**, and a refutation cannot be wider than what it refutes.

**The premise survived challenge; the output is narrower than I first wrote it.** The
`minerva-omnifold-38` lane tried to break the *"only remedy"* premise and reported the attempt failing:
`:473` names a second route in the same sentence (*"a receipt, **not a re-run**"*) and `:469-470` names

exist"*) — **but both read the same `TParameter`s, so both die on `ABSENT`. One stamp family, not two
remedies.** Premise holds.

**What this ground yields is therefore STAMP scope, not `P` scope.** By its own logic the claim's
content is bounded by what the receipt refuted, which is the stamp routes — so it reaches neither `M`
**nor the rest of `P`**, the hash route included. Stamp-scope coincides with `P`-scope on the four
cells only because `:68`, `:72`, `:73`, `:77` all happen to give stamp reasons: **contingent, not
structural.** The `P` boundary comes from §2.0, which is textual; this ground corroborates it and must
not be read as establishing it, or a later reader will apply it to a `P` cell whose reason is not a
stamp and get the wrong answer.

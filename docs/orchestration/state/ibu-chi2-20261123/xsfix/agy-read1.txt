## 1. Correctness Bugs

1. **`truth_projections` and `efficiency_mesh` call `th2d_edges` (which accepts `(16, 14)` transposed histograms) while assuming `(X = p_T, Y = p_||)` (`(14, 16)`).**
   - **Locations:**
     - `2d-unfolding/uq/reported_cells.py:79-94` (`th2d_edges`)
     - `2d-unfolding/plot_2d_cross_section.py:271-275` (`truth_projections`)
     - `2d-unfolding/plot_2d_cross_section.py:278-286` (`efficiency_mesh`)
     - `2d-unfolding/unfold_2d_omnifold_unbinned.py:1276-1308` (`project_xsec_1d`)
   - **Details:** `th2d_edges(h)` explicitly accepts both `(14, 16)` and `(16, 14)` histograms and returns `(pt_edges, pz_edges)` in both cases. However:
     - `efficiency_mesh(h_eff)` assigns `npt, npz = h_eff.GetNbinsX(), h_eff.GetNbinsY()` (`plot_2d_cross_section.py:281`) and builds `eff_arr` of shape `(nx, ny)`. On a `(16, 14)` input (`X = p_||, Y = p_T`), `pt_edges` has 15 edges (14 bins) and `pz_edges` has 17 edges (16 bins), while `eff_arr` has shape `(16, 14)` instead of the documented `(14, 16)` `[pT, p_parallel]`. Passing `(pz_edges, pt_edges, eff_arr)` to `ax.pcolormesh` (`plot_2d_cross_section.py:400`) raises a shape-mismatch error.
     - `truth_projections(h2d)` passes `(pt_edges, pz_edges)` from `th2d_edges(h2d)` to `project_xsec_1d` (`unfold_2d_omnifold_unbinned.py:1283-1308`). `project_xsec_1d` always loops `ix = 1..GetNbinsX()` for `"pt"` (multiplying by `GetYaxis().GetBinWidth(iy)`) and `iy = 1..GetNbinsY()` for `"pz"` (multiplying by `GetXaxis().GetBinWidth(ix)`). On a `(16, 14)` input, `"pt"` loops `ix = 1..16` into a 14-bin `TH1D` (bins 15–16 write into ROOT overflow/out-of-range bins) using `p_T` widths instead of `p_||` widths, and `"pz"` loops `iy = 1..14` into a 16-bin `TH1D` (leaving bins 15–16 at 0) using `p_||` widths instead of `p_T` widths.
   - **Impact:** Standard `unfold_2d_omnifold_unbinned.py` outputs are `(14, 16)`, where this does not trigger; any caller passing a `(16, 14)` `TH2D` (such as a release-oriented histogram) directly to `efficiency_mesh` or `truth_projections` hits a crash or silent bin corruption instead of either transposing or rejecting `(16, 14)`.
   - **Certainty:** Certain.

2. **No consistency check across histograms in `main()`, `plot_1d_projection`, `plot_panel_grid`, or `load_flux_bins_for_truth` (pre-existing, interacts with multi-grid inputs).**
   - **Locations:**
     - `2d-unfolding/plot_2d_cross_section.py:93-118` (`plot_panel_grid`)
     - `2d-unfolding/plot_2d_cross_section.py:166-178` (`_plot_1d_projection`)
     - `2d-unfolding/plot_2d_cross_section.py:245-268, 333-340` (`load_flux_bins_for_truth`, `main`)
   - **Details:**
     - `_plot_1d_projection` reads `edges` only from `h_xsec` (`hXSec_pt`/`hXSec_pz`) and reads only `GetBinContent` from `h_truth` (`hXSecTruth_pt`/`hXSecTruth_pz`). Even though `truth_projections` now gives `hXSecTruth_pt` the truth histogram's edges, any mismatch between `hXSec_pt` and `hTruth2D` (or `hXSec2D`) is silently drawn at `h_xsec`'s bin edges.
     - `plot_panel_grid` takes slice titles, `centers`, and `widths` from `h_xsec` (`hXSec2D`) and `edges`/`xlim` from `h_truth` (`hXSecTruth2D`) without verifying their axes match.
     - `load_flux_bins_for_truth` reads `hFlux_pt` (or the `--mcfile` fallback histogram) by bin index without checking its `p_T` bin edges against `hTruth2D`. If an input on the new grid lacks `hFlux_pt` and falls back to an old-grid `runEventLoopMC.root`, `compute_truth_xsec_2d` silently divides the new-grid truth bins by old-grid flux bins.
   - **Certainty:** Certain (note: pre-existing design assumption that all objects in one `--infile` share one grid).

## 2. Ways Output Could Be Altered on the Old Grid

On a standard `TH2D` input on the old `14 x 16` grid (`PT_EDGES` on X, `PZ_EDGES` on Y), **no values, strings, or output figures are altered**:
- `edge_label(x)` (`2d-unfolding/uq/reported_cells.py:70-76`) produces the exact same `"0.00"`..`"4.50"` 2-decimal strings as `f"{x:.2f}"` for every edge in `PT_EDGES`, because `abs(round(x, 2) - x) == 0.0 <= 1e-9` in `float64`.
- `th2d_edges(hXSecTruth2D)` (`2d-unfolding/uq/reported_cells.py:79-94`) returns the exact `float64` bin edges of `PT_EDGES` and `PZ_EDGES` stored on `hXSecTruth2D`, so `truth_projections(hXSecTruth2D)` passes identical edges to `project_xsec_1d` (`2d-unfolding/plot_2d_cross_section.py:274-275`).
- `efficiency_mesh(hEff2D)` (`2d-unfolding/plot_2d_cross_section.py:278-286`) extracts the same `eff_arr` values and `PZ_EDGES` / `PT_EDGES` arrays for `pcolormesh`.
- `2d-unfolding/plot_2d_threeway_fig13.py:43` imports the exact same `edge_label` definition moved to `uq/reported_cells.py`.

Only edge-case departures from standard old-grid `TH2D` inputs could change behavior relative to `BASE_XS`:
- **Non-`14 x 16` inputs:** `truth_projections` and `efficiency_mesh` now reject non-`(14, 16)`/`(16, 14)` `TH2D`s with `CellIdentityError` via `th2d_edges` (`2d-unfolding/uq/reported_cells.py:94`) instead of letting `project_xsec_1d` silently truncate/overflow. (Not an issue for the 14 x 16 analysis grid.)
- **`TH2F` (32-bit float) axes on the old grid:** If a `TH2F` (rather than `TH2D`) were passed to `th2_to_slices`, `float32(0.33)` is `0.33000001311302185` (`diff = 1.31e-8 > 1e-9`), so `edge_label` (`2d-unfolding/uq/reported_cells.py:73-76`) would format it as `"0.330000013"` instead of `"0.33"`.
- **`sys.path` import resolution (`2d-unfolding/plot_2d_cross_section.py:37-40`):** `_sys.path.append(_UQ)` puts `2d-unfolding/uq` at the end of `sys.path`; if an environment already has a different `reported_cells` earlier on `sys.path`, that module would shadow `uq/reported_cells.py`.
- **Certainty:** High (by code inspection; tests not executed locally).

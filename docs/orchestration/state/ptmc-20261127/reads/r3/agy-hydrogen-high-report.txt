## Part B — Findings in Draft r3

1. **[BLOCKER — class (c) FALSE STOP] §7's per-replica cost estimate omits dividing by the 4 concurrent lanes per node, stopping every valid pilot**
   - **Location:** [PTMC-DECLARATION.md §7](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/PTMC-DECLARATION.md#L388-L393).
   - **Evidence:** [PTMC-SCOPING.md](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/PTMC-SCOPING.md#L34-L35) packs 4 lanes of 64 CPUs per node (`8, two nodes, 4 lanes each`, `≈ 0.4` node-h for the pilot, and `0.0489` node-h per R replica, corresponding to `4 × 0.0489 = 0.1956 h ≈ 704 s` wall time per 4-lane wave, cf. OOFVC's `756 s = 0.21 h` on one node). However, [PTMC-DECLARATION.md §7](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/PTMC-DECLARATION.md#L389-L390) defines: *"The estimate of one R replica: per node, the maximum of the R replica lanes' step-level sacct Elapsed, divided by the units per lane. The pilot has one R replica, so its lane's step time is the estimate."* Because the pilot runs 1 unit per lane (`units per lane = 1`) across 4 concurrent lanes on a node, omitting `/ 4` (i.e. dividing by units per *lane* instead of units per *node*) makes the pilot estimate `≈ 0.20–0.21 node-h` per replica instead of `≈ 0.05 node-h`. The STOP condition (`pilot's charge + 199 × estimate > 11.5 node-h`) then evaluates to `~0.4 + 199 × 0.20 ≈ 40.2 node-h >> 11.5 node-h`, halting every correct pilot run before the 199 replicas launch.
   - **Fix:** Define the per-replica estimate as `max_lane(step_Elapsed) / (lanes_per_node × units_per_lane)` on each R-replica node, so in the 4-lane-per-node pilot with one R replica (`p_R_b1`), the estimate is `step_Elapsed(p_R_b1) / 4`. Also state that each unit in a lane runs as its own named `srun` step so step-level `sacct` isolates `p_R_b1`.

2. **[BLOCKER — class (b) gate fail-open] `C-COUPLE` checks only per-cell sums (`|T_orig,CV,j / D_CV,j − 1| ≤ 1e-9`), accepting runs whose bootstrap-coupling premise is false (and leaving `1e-9` unjustified)**
   - **Location:** [PTMC-DECLARATION.md §2.2](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/PTMC-DECLARATION.md#L135-L144), [§3.1 C-COUPLE](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/PTMC-DECLARATION.md#L249).
   - **Evidence:** [§2.2](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/PTMC-DECLARATION.md#L137-L141) notes that production's Phase-17 completeness coupling (`D*_j / T*_orig,j = D_CV,j / T_orig,CV,j`) requires `mc_truth_denom` (`D`) and original truth-passing signal rows (`T_orig`) to be the same events with the same weights, while [in_truth_phase_space](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/re2_driver_at_M.py#L66-L79) omits truth-vertex cuts. Checking only the cell sum `|T_orig,CV,j / D_CV,j − 1| ≤ 1e-9` passes runs where `D` and `T_orig` are *not* the same events/weights—for example, split vs merged weights (`w/2 + w/2` vs `w`, giving different Poisson(1) bootstrap variance), an out-of-vertex-cut row in `mc_signal_reco` offset by a missing truth-only miss to `1e-9`, or a defective driver reading `sig` into `hOFTruthDenom2D`. Both [collect_truth_denom_arrays](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/re2_driver_at_M.py#L666-L670) and [collect_signal_arrays_2d](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/re2_driver_at_M.py#L820-L829) already load `(truth_pt, truth_pz, w_truth)`, so per-cell count and multiset equality can be verified without event IDs. Additionally, `C-COUPLE` tests `"where either is positive"` without checking non-negativity, omits explicit assertions on `has_truth_only_misses` and `truth_denom is not None` ([re2_driver_at_M.py](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/re2_driver_at_M.py#L2441)), and provides no justification for `1e-9` (note: on a Phase-17/18 input with `nG1 = 0, nSigLoopNoTruth = 0` per [OOFVC-DECLARATION.md](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/OOFVC-DECLARATION.md#L296-L298), float64 summation in `TH2D::Fill` agrees to `~1.58e-14` per [oofvc-r3-score.json.txt](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/oofvc-r3-score.json.txt#L273), though any event dropped by `0 <= wr < 1e4` at [re2_driver_at_M.py](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/re2_driver_at_M.py#L777) or differing at `θ_μ = 20°` between C++ and Python `atan2` would break exact coupling and trip `C-COUPLE`).
   - **Fix:** Require `C-COUPLE` to check per cell (on `p_off_c` and `p_R_c`'s original rows): (1) non-negative values, (2) exact event-count equality `N_orig,CV,j == N_denom,CV,j`, (3) exact equality of the sorted `(truth_pt, truth_pz, w_truth)` multisets, and (4) explicit assertion of `has_truth_only_misses == True` and `truth_denom is not None` in the hunk, justifying the sum tolerance (`1e-12` or `1e-9`) from float64 summation order on non-negative weights (citing [oofvc-r3-score.json.txt](file:///Users/josephbailey/ptmc-reads/decl-r3-agy/inputs/oofvc-r3-score.json.txt#L273)).

# Note register round n2, N2-1: records entries cited by number (machinery commit, 2026-10-26)

**Authority:** the director's rulings of 2026-10-26, recorded in the n2 outline. The generated-numbers route was
approved, with `\input{records_entry_numbers}` in preamble.tex and main_note.tex left protected, under four conditions.

**This commit adds the machinery only.** The posted note still cites records entries by tag. Converting the note's 11
citations from `\texttt{<tag>}` to `\recentry{<tag>}` comes in its own commit, after the prose batches, which edit
the same files.

## Why generated numbers, not a cross-reference

`build_all.sh` builds main_records last, because main_records reads the note's labels (`\externaldocument{main_note}`).
Reading the records' numbers back into the note would make the two builds depend on each other. It would also put an
xr line in the protected main_note.tex, and make the posted note's flattened deposit export depend on an unposted
document's aux file.

## What it adds

**`check_note_records.py entry-numbers` writes `records_entry_numbers.tex`.**
- One `\@namedef{recentry@<tag>}{R1.<n>}` per full-width entry of app_provenance.tex, and the macro `\recentry{<tag>}`.
- An unknown tag stops the build with a named error.
- The counting rule is the label hook's in main_records.tex: every `\item[\texttt{<tag>}.]` (final period optional),
  in file order, numbered within the records section that app_provenance.tex opens. That section number is one more
  than the `\section` commands main_records.tex prints before it inputs app_provenance.
- **`--check`:** the committed file equals a fresh generation.
- **`--check-aux`:** every generated number equals main_records.aux's `\newlabel{rec:<tag>}`.

**preamble.tex** inputs the file, so the note, the primer and the records build define `\recentry`.

**RECORDS-PIN Q3** now also reads `\recentry{<tag>}` as a tag citation, and so does P6/P8's citation parser. For
every `\recentry{<tag>}` the posted note prints, Q3 requires the posted number to equal the tag's number generated
from app_provenance.tex and main_records.tex **at the pinned sha**, not from the working tree.

**P9's floor is extended** (director's condition (i) on the records commit).
- An entry that a records-move-ledger row records as added ("Section R1 entry `\texttt{<tag>}`", rows L-n2-1 to
  L-n2-6) must keep its label, whether or not the note cites it.
- This closes the gap the reviewer left open: renaming an uncited added entry's label passed. It now fails P9 (plant
  "added entry's label renamed").
- The P9 summary line now names both populations: "entries required for 11 cited tags and 6 added entries, 4 repeated
  records checked". It no longer says "cited tags with entries" (the reviewer's nit).

## The director's four conditions

**1. The export.**
- `bash build_all.sh --export-deposit DIR` gives rc 0.
- The flattened `main_note.tex` holds the generated file inline: all 17 `\@namedef{recentry@<tag>}` definitions and
  the `\recentry` macro (19 lines mention `recentry@`), and no `\input{records_entry_numbers}`.
- The export's extracted-text proof passes: the exported tree's PDF text equals main_note.pdf's.
- **Planted stale file.** `{R1.12}` was changed to `{R1.13}` in records_entry_numbers.tex. `build_all.sh
  --export-deposit DIR` then exits 1 at `ENTRY-NUMBERS :: FAIL (records_entry_numbers.tex is missing or stale …)`,
  before any latexmk run, and DIR stays empty. The file was then restored, and `--check` passes.

**2. Scope.** The generator is a mode of check_note_records.py, beside the label hook's description. It shares
`ENTRY_LABEL` with P9. `--self-test-entry-numbers` checks five things:
- the generator numbers a fixture R2.1–R2.3. The fixture has a `\shortstack` table row, an item without its final
  period, and two lists;
- a fresh file passes `--check`;
- a stale file fails `--check`;
- a records label that differs fails `--check-aux`;
- **with pdflatex,** main_records.tex's own label hook, copied from the file, numbers the same fixture exactly as the
  generator does.

Power test: a generator that requires the final period fails two of these checks, the fixture count and the LaTeX
agreement:

```
FAIL label hook and generator disagree: hook {'tag-a': 'R2.1', 'tag-b': 'R2.2', 'tag-c': 'R2.3'}, generator {'tag-a': 'R2.1', 'tag-c': 'R2.2'}
```

Without pdflatex (CI), the agreement case reports SKIP, and the summary says "4 checks as expected, 1 skipped".

**3. Where the checks run.**
- `build_all.sh` runs the self-test and `--check` before any build, and `--check-aux` after the records build.
- `record-checks.yml` (CI, no LaTeX) runs `--check`, `--self-test-entry-numbers` and `pin` (Q1–Q4).
- RECORDS-RULES.md "Where the checks run" says so.

**4. Q3 at the pinned sha.** The pin self-test adds two cases:
- a `\recentry` citation whose number holds at the pin passes;
- an entry inserted before the cited one after the pin, with the numbers file regenerated from the working tree,
  fails: `Q3 sec_a.tex cites tag-b as 'R1.2', but at the pin … its records entry is numbered 'R1.1'`.

`--self-test-pin` now has 11 of 11 cases.

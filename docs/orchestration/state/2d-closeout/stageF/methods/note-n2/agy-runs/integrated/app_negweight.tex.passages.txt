=== PASSAGE AC-4 (app_negweight.tex) ===
BEFORE:
For the existing endpoint unfolds, produced in July 2026, purity is established by elimination. Neither of the two job scripts that could have produced them sets the driver's background-mode option (\texttt{-{}-bkg-mode}), so the driver ran with its default, purity; the driver announces its mode only on its negative-weight code paths, and the logs of these lateral-band unfolds contain the purity code path's signature line and no mode announcement. The option and the announcements already existed when the files were produced, so the absence of an announcement is evidence of purity. Current production fixes the background treatment in a configuration object that rejects every other mode. The standard job script passes the option explicitly from that configuration rather than inheriting the default, and the value is written into the record of every endpoint unfold as it is produced. This changes how the treatment is documented, not the physics: the background treatment of a future component can be read from the component itself rather than inferred from the absence of an option.

The standard chain uses purity by choice, on two grounds (Ref.~\cite{NoteRecords2026}, \texttt{oi6-oi8-oi126}). First, mixing background treatments inside one covariance is worse than either consistent choice: inserting a lateral-band block built with negative-weight subtraction into a central and vertical set built with purity subtraction is a mismatch, not an upgrade. Second, switching would have required rerunning every unfold above and would have invalidated the flux-corrected covariance, which had just been chosen for use. This consequence, not the computing cost, decided the choice. The background treatment has been revisited in two dimensions: the closure test below is its result, and the 2D result and its covariance use the refined estimator. For the five-dimensional central value, which still uses purity, the revisit is open.

=== PASSAGE AC-6 (app_negweight.tex) ===
BEFORE:
\paragraph{Refined negative-weight subtraction.} Refinement used the unfold's deterministic GBDT configuration, independent injection and subtraction halves of background simulation, and bootstrap replicas that individually resampled every pseudo-event and refit refinement. It preserves the signed total to $3\times10^{-6}$ and clips \SIrange{0.01}{0.05}{\percent} of events. Corner bias falls from \SI{1.66}{\percent} to \SI{0.24}{\percent}, but residuals in some joint cells fail the nominal closure criterion, which allows none of the 153 reported quantities a mean residual beyond 3.6 standard errors of the mean ($|t|>3.6$, the two-sided 5\% level, Bonferroni-corrected over the 153), or beyond half its bootstrap standard deviation with $|t|>3$. The data difference's sign pattern matches simulated purity bias at an order of magnitude smaller size; the difference is method sensitivity, not a measured bias. With either treatment, the estimator does not follow generator-sized $\Eavail$ shape changes. No coverage test was run. Reducing one bias does not itself qualify an uncertainty, so this result does not close the revisit of the five-dimensional background treatment (\S\ref{sec:negweight-footing}).

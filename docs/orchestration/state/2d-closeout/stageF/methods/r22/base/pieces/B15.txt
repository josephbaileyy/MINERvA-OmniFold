Result package and reproduction limits

This appendix describes the local replay package that exists, RC7, and specifies the broader eventlevel and covariance release. It states which identities are fixed and what each part does and does
not reproduce. Rebuilding this note’s PDFs assembles documents; it does not reproduce scientific
results.
The code paths and file names in this appendix and in App. H refer to the snapshot of the
code repository, [repository].
Release status. RC7, a local release candidate with a README, checksums and a replay
verifier [97], has not been deposited or released under a publication tag. RC7’s own verifier, run on
the packaged files in an empty directory, reproduces the recorded observed statistics of the joint tests,
the p value and count of every test and variant and the decision of every test, the robustness results
and the power figures, and every figure number that it checks. It does not recompute the recorded
stability of the observed p values under the data’s rounding noise. The package, about 16 MB of
sufficient inputs, reproduces the joint-test p values, decisions, robustness labels and power results;
the same results in the reading with the recovered pseudo-experiments added to the calibration and
the variant shifts recomputed on all draws (§11.6); the matched coarse-projection comparison (§11.7);
and the fine-grid L2 ratios of condition (i) (§11.4). It also regenerates, from packaged arrays, figures
drawn for the earlier version of the article for which it was assembled: the (Eavail , W ) excess map,
which this note prints as Fig. 24, the null distributions of the joint tests, which it prints as Fig. 31,
and one-dimensional generator projections, which neither this note nor the article now prints. RC7’s
two-dimensional curve is the exact-split one, which was the two-dimensional central value when the

package was assembled. The article’s two-dimensional validation figure and its numbers were instead
regenerated separately, from the committed values and covariance of the refined LightGBM result,
with RC7’s plotting code extended to draw this analysis’s band.
Contents and use. The package holds the sufficient inputs of the joint tests, as evaluated
for the decisions and in the reading with the recovered pseudo-experiments added; the arrays
behind the figures drawn for that earlier version; the noise-free differences behind the L2 ratios;
an inventory of the analyzed AnaTuples; the replay and figure code; and the expected outputs.
With the package’s pinned requirements (numpy, scipy and matplotlib) installed in a fresh Python
environment, the package’s verifier (publication/release/verify_rc.py in the repository), run
from the top directory of the unpacked package, performs every replay and figure check and prints
VERIFY: PASS if all agree. In the two replays of the joint tests, floating-point values must agree to
a relative 10−12 , and integers and decisions must agree exactly. Each quoted figure number must
agree with its printed value to within half a unit of its last printed digit, and the L2 ratios must
reproduce their printed range; for Figs. 1–3 of that earlier version themselves, the check is that the
three figure files are produced. The package carries the 20 rounding jitters from which the stability
of the observed p values (§11.4) can be recomputed, but no packaged script does so.

G.1

What today’s reader can and cannot recompute

The public ancillary files of Ref. [3] supply the published inputs for the comparisons to its central
values and covariance, the standardized differences, the tension anatomy, and the MINERvA Tune v1
model comparison.
They do not reproduce this analysis’s unfolded 2D uncertainty construction. RC7 supports replay
of the higher-dimensional inference from sufficient inputs, but not extraction from the archived
pseudo-experiment products, event-level unfolding, or the quoted closure, bias and covariance-status
measurements. Nor does it reproduce the 2D uncertainty and coverage figures, the low-recoil
comparisons, the recoil-response sensitivity, or the proxy convergence rate of joint-test condition (i).
The multiplier scan of the joint tests is recomputable from RC7’s sufficient inputs with the scan
code of Ref. [56], but it is not part of RC7’s own verification. The pseudo-experiment products
are archived (about 2.3 GB). An earlier version of the package, RC1, was replayed from an empty
directory by a separate AI agent session (Opus 5.5) that had no access to the repository and used only
the package and its README; its verifier passed. Event processing requires the earlier production
of MINERvA open-data AnaTuples, event-loop outputs, and the generator samples used here.
The record of Ref. [98] identifies all 2,374 inventoried input files (2,307 AnaTuples and 67 flux,
reweight and parameter files) by SHA256 checksum; RC7’s own inventory lists their names, sizes and
modification times, without checksums. The same record, dated 2026-10-10, verifies copies of all 1,885
data, flux and parameter files on NERSC project storage; it identifies the 489 simulation AnaTuples
by checksum but holds no preservation copy of them. Neither the checksums nor the preservation
copies are a public deposit, and they do not make the full event-level analysis reproducible from the
small candidate package.

G.2

Release schema

The broader result package must contain every item below; RC7 does not contain all of them. A ✓
marks identities or values already fixed (bin edges: §G.3; checksums: Ref. [37], identities already
fixed); the rest are packaging. A fixed identity says which object is meant; it does not qualify the
object scientifically.

1. Reporting bin edges and units, per axis ✓: pT and p∥ in GeV/c, Eavail , q3 and W in
GeV, with each wide terminal catch bin identified.
2. The flattened-cell ordering ✓: the dense 14 × 16 × 7 × 7 × 6 grid in C order, with the
reported subset supplied as an explicit index array, never inferred from a positivity cut.
3. Central values: the five-axis array and every projection quoted, each with its own checksum,
on the density scale in cm2 /nucleon divided by the product of its kept axes’ units.
4. Covariances ✓: the five-axis covariance of the configuration-(a) central value and its (Eavail , W )
projection, with the algebra of Eqs. (4)–(5), the declared centering variant, and the band
partition.
5. Masks ✓: the support mask, the pinned mask (bins where the inflation denominator vanished
and g was declared 1), and the unreported-cell mask.
6. Projection matrices ✓: M itself, with its content checksum, its shape, and the explicit
statement that its entries are the dropped axes’ bin-width products, which is needed to specify
the destination units.
7. Generator predictions: the four truth-level (Eavail , W ) predictions (GENIE-CV,
GENIE+Valencia 2p2h, NuWro, GiBUU) and the MINERvA Tune v1 ancillary model,
as arrays on the release binning rather than figure curves, each with generator version,
configuration, target and flux. GENIE and NuWro require the flux-repaired predictions of
2026-09-27 (per-event reweight to the analysis PPFX flux plus the 50–100 GeV supplements);
GiBUU requires its reweight to the same flux convention (§7.6).
8. Provenance: for each object, the producing code revision, the job, and the checksum of the
bytes read back from the closed file. Of these, only the assembling revision and job of CZ , job
of CEW and read-back row-index checksum are fixed. No producing revision or job is recorded
for the other objects, and the assembled package carries none.
9. One minimal worked example: §G.4.
10. The four measurements that travel with the five-axis covariance of the configuration-(a)
central value (§9.6), carried in the package that readers will quote and not only in this note.

G.3

Bin edges

The bin edges are the one thing a reader cannot recover from a checksum:
• pT , GeV/c: 0, 0.07, 0.15, 0.25, 0.33, 0.40, 0.47, 0.55, 0.70, 0.85, 1.00, 1.25, 1.50, 2.50, 4.50 (14
bins).
• p∥ , GeV/c: 1.5, 2, 2.5, 3, 3.5, 4, 4.5, 5, 6, 7, 8, 9, 10, 15, 20, 40, 60 (16 bins).
• Eavail , GeV: 0, 0.1, 0.2, 0.4, 0.8, 1.5, 3.0, 100 (7 bins).
• q3 , GeV: 0, 0.2, 0.4, 0.6, 0.8, 1.2, 2.0, 100 (7 bins).
• W , GeV: 0, 1.1, 1.4, 1.8, 2.2, 3.0, 100 (6 bins).
The last bin on Eavail , q3 and W is a catch bin to 100 GeV, and the pT × p∥ grid carries the 19
unreported high-pT , low-p∥ acceptance cells of §3.5.

UNDECLARED: when the projection was built, it had not been decided whether an acceptance correction
is needed at the destination binning. The package must carry this field with its value until that is
decided, so that no default in the data format makes that scientific choice.

H

Codebase layout and terminology

The analysis chain has four components; the note refers to them by the names in italics below.
• Event loop (C++): runEventLoopOmniFold, built on the MINERvA Analysis Toolkit (MAT)
and the MINERvA-101 framework. It reads production AnaTuples, applies selection and
systematic-universe machinery, and writes per-event ROOT trees.
• Event-loop outputs (omnifiles in the code): per-event records for data, for simulated signal
with paired true and reconstructed quantities, for simulated background, and for the truthlevel efficiency denominator, together with the exposure in protons on target (POT). The
_universes_full variants add per-universe weight and shifted-kinematics branches.
• Driver (Python): per-analysis orchestration in 2d-unfolding/unfold_2d_omnifold_unbinned.py and its N -dimensional generalization nd-unfolding/unfold_nd_omnifold_unbinned.py. The driver builds training arrays from the event-loop outputs, applies the
background subtraction its background-mode option selects (by default the purity weight;
§3.1), runs the engine, and extracts the cross section.

• Engine (Python): unbinned_unfolding/python/omnifold.py implements the OmniFold iteration independently of the learner backend: LightGBM for the central value and the uncertainty
ensembles, scikit-learn’s exact-split gradient boosting (exact) for the cross-check, its histogram
gradient boosting (hist) as an alternate, and a multilayer perceptron (MLP) for a further
cross-check.
Point-cloud (PET) code is under nd-unfolding/pet/ (App. F).
Scripts, figure files and stored outputs call training-seed variation seedscan; the two names
denote the same variance source. The quoted training-seed block is assembled by the aggregation
step of the 2D production, not by the seedscan scripts.

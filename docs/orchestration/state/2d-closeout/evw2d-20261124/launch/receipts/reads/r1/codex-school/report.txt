## C. Findings and fixes

- **BLOCKING — Post can pass a failed or unaccounted job.** `evw2d_post.sh:23–35,55–67,82` ignores a failed queue lookup, claims the only post directory before resolving accounting lag, and returns success based on product checks alone. Query a successful user queue listing for exact job-ID membership. Obtain exactly one terminal allocation row from `sacct` before claiming `post/`. Keep receipts for failures, but require `COMPLETED`, `0:0`, and one node for PASS. Validate numeric charge fields and bind `run.json` to the approved config digest. `accepted()` validates the product, while the wrapper’s final stdout record provides its allocation ID (`evw2d.py:1054–1067,1142–1147`).
- **BLOCKING — Cleanup can proceed after post returned failure.** `evw2d_post.sh:55–68` writes `verify.txt=PASS` before checking `accepted()`. If the post interpreter fails while products are good, `evw2d_cleanup.sh:18,27–39` can later accept those products and delete the staged copies. Post and cleanup also ignore failures copying receipts, making manifests, or creating archives. Publish one final post PASS receipt tied to the job, config, and product manifest only after acceptance, terminal success, and receipt creation succeed. Require it in cleanup. Check the deletion ledger copy and archive creation, and publish archives by rename after successful creation.
- **BLOCKING — Submission can outrun the allocation check.** `evw2d_connect.sh:168–188` submits an eligible job before it persists and validates the ID. Malformed submit output or a failed ID write can leave a live job. A transient `scontrol` error with empty output cancels a correct job, while matching stdout with a nonzero status passes. Submit held, check and persist the ID, validate successful `scontrol` output with exactly one matching job and each required field, then release. Check cancellation status and confirm the terminal outcome in `sacct`. Keep the independent batch gate.
- **BLOCKING — Certificate check can pass the wrong credential or a future-dated one.** `evw2d_launch.sh:13–24,31–48` checks only the end time, masks `ssh-keygen` failure through the pipeline, and leaves SSH/SCP to select credentials independently of `EVW2D_CERT`. Check successful command output, both validity endpoints, and a successful clock read. Use `TZ=UTC` for both OpenSSH’s display and BSD `date` parsing. Configure the checked certificate and matching identity for the hop that uses sshproxy, including fetch.
- **SHOULD-FIX — The 64-CPU step depends on unverified Slurm defaults.** `sbatch_evw2d.sh:2–9,69–79` requests `-c 64` and `--mem=200G` only at the step. `--exclusive` gives access to exclusive CPUs but does not explicitly reserve 200 GiB or select a Linux affinity mask of 64 logical CPUs. The real running record shows a 64-CPU allocation with explicit `--cpus-per-task` and memory. Reserve the required memory and CPUs at submission, select the supported CPU binding, and use the print-only step with the same resource and binding options to check `len(os.sched_getaffinity(0)) == 64` before Python runs. The `64/1/1` thread exports are correct (`sbatch_evw2d.sh:77`, `evw2d.py:892–897`).
- **SHOULD-FIX — Environment setup is handled differently across phases.** The batch temporarily disables `noclobber` for `source`, while post and cleanup source under `noclobber` (`sbatch_evw2d.sh:62–68`, `evw2d_post.sh:19,58–66`, `evw2d_cleanup.sh:14,27–31`). If the pinned setup overwrites an existing regular file through `>`, login staging and the job can succeed while post or cleanup fails. The setup file is absent from the snapshot. Source it consistently in a lane-local working directory, keep exclusive receipt redirects outside that setup scope, and check the selected Python after sourcing. Also check `sys.pycache_prefix` during the login preflight, matching `evw2d.py:207–216`.
- **SHOULD-FIX — Budget, custody and fetch receipts have unchecked failures.** `evw2d_connect.sh:68–75,81–82,95–96,136` can mask upstream failures in `stat | tee`, `git status | wc`, and the `iris` pipeline. The budget parser also rounds before enforcing the cap. Check producer status directly, require one numeric balance row, compare before rounding, and check both source stat receipts. At `evw2d_post.sh:69–75`, record the final atime after the last product read and require successful stat on the expected files. At `evw2d_launch.sh:33–38`, distinguish an absent optional archive from an SSH failure, and propagate local checksum failure.
- **SHOULD-FIX — The temporary-file placement needs an explicit ruling.** `evw2d_launch.sh:45–48` creates a script in `/dev/shm` before the lane claim, while declaration §7 says launcher temporaries stay inside the lane. Keep the exclusive claim and either bind an explicit exception for the private trampoline or verify the transmitted script in memory before executing it.
- **MINOR — Improve refusal receipts and early diagnostics.** The early `bail` at `evw2d_connect.sh:46–58` gives no condition, and `sbatch_evw2d.sh:38,75–76,83–86` interpolates unescaped strings into JSON and ignores final receipt-write failure. Print the failed precondition and serialize refusal strings with JSON escaping. Propagate a failed final receipt write.

**NOTE — Binding and platform checks.** The four binding fields align with `deploy_M`, `deploy_C`, `stage` and `out` under the same lane (`fill_pins.sh:33–49`, `evw2d_connect.sh:97–114`, `evw2d.py:155–204,1115–1146`). The reviewed config digest matches the supplied bytes. The digest heredocs expand their pins, the Python heredoc receives values as quoted arguments, and stage/run/cleanup use the expected CLI. Post’s column-67 extraction matches the wrapper’s two-space manifest format, including the fallback ordering. BSD `date` and `shasum` are used on the Mac. GNU `stat`, `sha256sum --strict`, and `timeout` are used on Linux.

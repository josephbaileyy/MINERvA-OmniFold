# PG offline record

`PG-RECORD.json` is the interpretation for PG's probe. It is generated by `build_record.py` from public files only,
and `PG-RECORD.md` shows the same content for reading. For each spent and candidate tune, the record gives the files
that define its CCQE and 2p2h models, the classes they resolve to and the novelty verdict. It also gives the sha256
pins the probe compares on the node, and the spline and README digests of SciSoft's genie_xsec tarballs. The probe
itself only checks byte identity against these pins.

## Inputs

`record-sources.json` lists every input with its sha256. All of them are public.
- SciSoft `genie-3.04.00-sl7-x86_64-e20-prof.tar.bz2`, from https://scisoft.fnal.gov/scisoft/packages/genie/v3_04_00/,
  extracted. `--genie` is its `genie/v3_04_00`.
- SciSoft `genie_xsec-3.04.00-noarch-<Q>.tar.bz2` for Q = G1810a0211b-k250-e1000, AR2320i00000-k250-e1000,
  G2111a00000-k250-e1000, G1802a00000-k250-e1000 and GDNu2001a00000-k120-e200, from https://scisoft.fnal.gov/scisoft/packages/genie_xsec/v3_04_00/. Only `data/gxspl-NUsmall.xml`,
  `data/README` and `ups/genie_xsec.table` are needed. `--xsec` is their `genie_xsec/v3_04_00/NULL`. SciSoft lists 8
  qualifiers for v3_04_00, and G2111b00000, G1802b0211b and G1802a0211b are not among them.
- GENIE-MC/Generator at tag R-3_04_00:
  - the recursive git tree, `api.github.com/repos/GENIE-MC/Generator/git/trees/R-3_04_00?recursive=1` (`--tree`);
  - the raw copy of each pinned config file, `raw.githubusercontent.com/GENIE-MC/Generator/R-3_04_00/config/<path>`,
    saved under `--github` as `<path>` with `/` replaced by `__`.

- SciSoft's genie tarball and G2111a00000 tarball are also given whole (`--genie-tarball`, `--private-tarball`).
  They give `genie-manifest.json`, every member of the genie product with its sha256 or link target, which the
  trace-check pins against. They also give `G2111a-members.json`, slot 1's private product, with 17 members: 9 files,
  6 directories and 2 links inside `data/`. Absolute names, `..` components, links leaving the tree and special
  files are refused.

**Provenance of the private product.** The A1 re-download on 2026-11-24 has sha256
`ae159887772a54891fc4bddb189ab108d74c4a48db68c13ed7166524e8797590`. That equals the earlier download of the same
SciSoft URL the same day, recorded in `record-sources.json` at `a754e4a4` and `b31559e2`. SciSoft publishes no
checksum. Two reads agreeing show the bytes did not change between them; they don't show the bytes are the
publisher's. The independent anchors are the two spent tunes: their SciSoft spline and README equal F1's CVMFS pins.
The product's UPS version file declares `PROD_DIR = genie_xsec/v3_04_00/NULL/G2111a00000-k250-e1000`, relative to
its database, so it sets up from a private `PRODUCTS` directory.

## root-schemas.json

`root-schemas.json` holds the gst schema every published gst must match: its keys (class, name, title, less the
file's own records) and its StreamerInfo's sha256. It is `null` until B3's replay records the schema of its 100-event
gst (`replay.json` `gst_schema`) and the director confirms it. Until then `pg_generate.sh` refuses before any step.

## Reproducing

```
python3 -I build_record.py --genie <genie/v3_04_00> --xsec <genie_xsec/v3_04_00/NULL> --github <raw copies> \
    --tree <tree.json> --sources record-sources.json --genie-tarball <genie tarball> \
    --private-tarball <G2111a00000 tarball> --out <dir>
```

The output is deterministic: two runs on the same inputs gave identical files. `nm` (with `-D --defined-only`) must
read ELF; the record was built with macOS's `/usr/bin/nm`.

## What it found (2026-11-24)

- **The candidates.** Each is novel, with agreeing branches. In 2p2h, G21_11b_00_000 and G21_11a_00_000 share
  `SuSAv2MECPXSec` with AR23_20i_00_000, the overlap §4.1 discloses. G21_11a differs from G21_11b only in
  `HadronTransp-Model`: hA versus hN. G18_02a_00_000 has G18_02a_02_11b's model classes, with no tune directory.
- **The splines.** SciSoft's splines and READMEs for the two spent tunes equal F1's CVMFS pins.
- **The tag.** All 38 pinned config files from the SciSoft build are byte-identical to the GitHub tag's.
- **The classes.** Every class is in the build's ROOT dictionary, with a defined default constructor.
- **GDNu20_01a_00_000** (surveyed for the director, on CVMFS as GDNu2001a00000-k120-e200) is a dark-neutrino
  coherent tune.
  - Its ModelConfiguration sets only `XSecModel@genie::EventGenerator/COHDNu` = `BertuzzoDNuCOHPXSec`, and its
    TuneGeneratorList enables only `COHDNu`.
  - Its spline holds 294 `BertuzzoDNuCOHPXSec` splines and no charged-current process.
  - It has no CCQE or 2p2h class, so it gets no novelty verdict.
  - Its README says `version v3_02_00 qualifier GDNu2001a00000:k120:e200`. Its range is 120 knots up to 200 GeV,
    against F1's `-e 0,100` (run_gevgen_v3.sh:55, gen5d_v3.py `E_HI`), so the 200 GeV maximum would cover F1's flux.
    The tune has no CC events to give, whatever its range.
- **G21_11a's MEC splines.** G21_11a's MEC-NC model is `EmpiricalMECPXSec2015`; all 864 of those splines are
  `Weak[NC],MEC`. Its MEC-CC is `SuSAv2MECPXSec`, which covers all 288 CC MEC splines.
- `SLOT1-PRIVATE-PRODUCT.md` answers the director's question on using G21_11a from a private product directory.
- **GXMLPATH.** Every genie_xsec UPS table read here runs `pathPrepend(GXMLPATH, ${UPS_PROD_DIR}/data)` (table
  line 19). These are G1810a0211b, AR2320i00000, G2111a00000, G1802a00000 and GDNu2001a00000.
  - After `setup_genie_v3.sh`, GENIE therefore searches the spline product's `data/` before `config/<CMC>/<tune>/`,
    `config/<CMC>/` and `config/`.
  - F1's own runs of G18_10a_02_11b and AR23_20i_00_000 inherit the same prepend, as PG's would.
  - The two `data/` directories extracted in full (G1810a0211b, GDNu2001a00000) hold no file named like a GENIE
    configuration file.
  - This record pins the genie product's directories only. The director accepted that the probe rebuild pins each
    used tune's `data/` listing from the node, by names only.

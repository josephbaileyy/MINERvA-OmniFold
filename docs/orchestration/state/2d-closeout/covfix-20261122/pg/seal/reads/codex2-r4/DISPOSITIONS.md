## Seed-bearing artifacts (folded into this round by the director, 2026-11-25)

codex-school's read of tune-generator's PG at 5f141f7a found that gevgen names its outputs by the run number, which is
the seed (`gntp.<seed>.ghep.root`, `genie-mcjob-<seed>.status`). The director ruled that raw traces never leave W, that
the hash of a seed-bearing file is itself seed-bearing, that a code-enforced leak scan runs over every byte leaving W
where the seed is known, and that every seed-named artifact is inventoried. cov2d's review found that the sealer
already meets the ruling by construction: everything under W is encrypted, plaintext hashes leave memory only inside
the encrypted manifest, and only ciphertext hashes are published, each over a random salt and prefix. It proposed the
items below; the director gave a GO for all of them and folded them into this round, so that one confirm read covers
everything. **Each was reproduced by a failing test on the round-4 code before its fix** (`REPRO-seedbearing.txt`:
`covfix_seal.py` `199ec719…`, `covfix_pg.py` `e1acebf9…`, test file `0a0a53dd…`). That run had 7 failures and 11
errors. A direct run of the round-4 code also printed a planted seed (in comm, then in exe) and a plaintext hash on
stdout. After the reproduction run, one assertion in the token test was corrected: it had checked a basename that the
tokens themselves contain, and it now checks the run's unique temp-dir name.

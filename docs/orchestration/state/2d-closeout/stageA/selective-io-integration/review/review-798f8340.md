### MINOR-1: a fourth frozen package pins the old driver and fails at HEAD, but nothing routes it

- **Where:** `Q/speed/bench/pinned.py:14-31` (`BASE = 5ac9706a…`, which checks that the driver's git blob is `e19aeb6d`, the `3cc5adc7…` driver). Its verification check `Q/speed/bench/test_prototypes.py:23` calls `pinned.load_driver()` when the module is imported. The speed REPORT lists it as `test_prototypes.py: 11 tests OK` (`Q/speed/REPORT.md:352`).
- **Measured at `798f8340`:** `RuntimeError: … blob bf2d7b58… != pinned e19aeb6d… at 5ac9706a`, rc 1.
- **Its own commit is fine:** the package bytes at HEAD equal those at `318d3e45` (`git diff --quiet`, rc 0), and the driver blob there is `e19aeb6d`. I did not run the test at that commit, because it needs the synthetic trees.
- **What the record misses:** RECORD §1, §5 (lines 100–120), CITABLE FOR (line 7) and the commit subject all list exactly three frozen packages: SB1, XR and XR-Linux. The delivery did not cover this one either. It left `speed` out of its caller population (`Q/selective-io/REPORT.md:289`) and out of §7.2/§10.1.
- **Failure scenario:** someone re-runs the speed lane's recorded verification at HEAD and gets an import-time RuntimeError that no routing record explains. They either treat it as a regression or "repair" the frozen pin. The test fails closed, so no wrong number is produced. That is why this is MINOR.
- **Fix:** add a row to §5, e.g. "speed `Q/speed` — bytes equal `318d3e45`; at HEAD `bench/pinned.py` refuses the new blob by design; run at `318d3e45`". Also widen the "three packages" wording in CITABLE FOR and in the routing paragraph.

## 1. The defect

The bound V0 (declaration §2.1, `fd_xcov_steps.cmd_v0` at M = `260e299b`) required three strings in each of RE-2's
replica logs `partb/logs/S1_<b>.log`, for b = 1–100: the regenerated data, MC and background draw sums, in
re2_driver's print format (`fd_xcov.draw_sums_line`).

**The background string cannot exist in those logs.** re2_driver prints `bkg factor sum=…` only in the purity branch
(`2d-unfolding/re2/re2_driver.py:2123`). RE-2 ran in negweight-refined mode, so the line was never printed. V0 at M
therefore failed the draw check (0 of 100 replicas matched) and read route A:

- `$R/v0/v0.json`;
- every other V0 leg passed: the counts, the MC rows and both joins.

**The background sum was recorded, in each replica's `xsec.root`.** re2_driver writes it there as the `p1Streams`
TNamed (`re2_driver.py:2221-2230`, written at `:2530-2531`). The record holds:
- `bootstrap_seed`;
- `seed_offsets` {data 0, mc 10,000,000, bkg 20,000,000};
- `n` and `sum` for each stream.

## 2. The change

**The background leg.**
- `fd_xcov.p1_streams_record(xsec_bytes)` parses that TNamed with uproot. It returns None if the file has no
  `p1Streams` key.
- `fd_xcov.bkg_stream_check(rec, b)` compares the record with the stream regenerated by `fd_xcov.draws_2d` (the
  function route B's mapped replicas draw from). It checks four fields: `bootstrap_seed` = b, `seed_offsets.bkg` =
  `SEED_BKG` (20,000,000), `n.bkg` = 658,227, and `sum.bkg` = the regenerated sum. The sum is integer-valued, so it is
  compared exactly. Any difference, or a missing record, fails the leg.

**The bytes are checked first.** `cmd_v0` reads each `partb/out/S1_<b>/xsec.root` through `Inputs.bytes`. That opens the
file O_NOATIME and refuses unless its sha256 is the pin in `fd/xcov/INPUTS.sha256`; all 100 are pinned there at M.

**The data and MC legs are unchanged.** They are the same `draw_sums_line` strings, searched in the same logs.

**V0 passes iff** the counts, the MC rows, both joins and all three legs for all 100 replicas hold (declaration §2.1,
with the background leg replaced). `v0.json`'s `draw_check` now also records:
- `matching_by_leg`;
- up to five replicas' background failures.

**Where the amended V0 writes.** `fd_xcov_steps.V0_DIR` = `v0-a1`. The amended V0 writes `$R/v0-a1/`, and refuses if
`v0-a1/v0.json` exists. BOOT and K read `v0-a1`.

**The first run stays as the record.** `$R/v0/v0.json` and its log are not touched.

**The job script.** `x_boot.sh` changes its `cd` from `$R/deploy` to `$R/deploy-a1` (§3), because BOOT reads `V0_DIR`.

**Unchanged:** V1's code (`cmd_v1`, `universe_list`, `weight_files`) and `x_v1.sh`. V1 does not read V0, so the V1 probe
(job 60678999) and the full V1 (job 60679146) run from `$R/deploy` at M stand.

**The tests (condition 2).**
- **PASS:** the real record, checked as replica 1, against the regenerated stream (sum 659,094 over 658,227 factors).
- **FAIL:**
  - a seed offset of 20,000,001;
  - a stream size of n ± 1;
  - a sum of ±1;
  - a bootstrap seed of 2;
  - a record with no `sum` key;
  - the real record checked as replica 2;
  - a stream regenerated with n − 1;
  - a regeneration at the wrong offset;
  - a ROOT file of the same format without `p1Streams`.
- **The guard's own mutants:** three edits to `bkg_stream_check` were each caught by `BkgLeg`, then reverted, with the
  file `cmp`-verified (receipt):
  - comparing the sum with itself;
  - dropping the n comparison;
  - treating an absent record as empty.

**Where the tests run.** `BkgLeg` needs uproot, so it runs under omnifold_py310, where V0 runs, and locally. Under
root_6_28 it is skipped.

3. New Findings

N1. [SHOULD-FIX] regrade_vf.py:302, 349 — `evaluation_controls()` calls `rc.r_chi2` without catching `ZeroDivisionError`, and `run()` does not catch it.
    `split()` wraps `rc.r_chi2(E, C_base, C_add)` in `try ... except ZeroDivisionError` (regrade_vf.py:182-185) so degenerate inputs raise `Stop`. However, `evaluation_controls()` runs earlier and calls `r0 = rc.r_chi2(E, C_T, C_add)` at line 302 without checking `E.shape[0] >= 2` or catching `ZeroDivisionError`, and `run()` at line 349 catches only `(Stop, OSError, ValueError, KeyError)`.
    Concrete failure scenario: Calling `evaluation_controls`, `evaluate_arrays`, or `run()` with a finite all-zero `cap["E"] = np.zeros((300, 16))` (or constant rows across toys, or zero `C_T + C_add`) passes `finite()` at line 295 and raises an unhandled `ZeroDivisionError` inside `regrade_crep.r_chi2` (`regrade_crep.py:141`: `(M - 1.0) / se` with `se == 0.0`, or `regrade_crep.py:121` with `ndf == 0`) instead of raising/recording `Stop`. (Cannot occur on valid non-degenerate draws.)

N2. [SHOULD-FIX] test_regrade_vf.py:104-123, 334-344 — `split()`'s returned `"SE"` and `"readings"` (and `"ndf"`, `"n"`, `"R_chi2_reading_regrade"`) are never verified against direct computation.
    `test_split_matches_a_direct_computation` (test_regrade_vf.py:104-123) checks `F`, `B`, `tau`, `M_prime`, `M_full`, and `sum(shares)` (with `test_split_shares_are_each_term_over_m_full` checking individual `shares` and `B_raw`), but never asserts `s["SE"]`, `s["ndf"]`, `s["n"]`, `s["readings"]`, or `s["R_chi2_reading_regrade"]`. `test_readings_use_their_own_se_keys` (test_regrade_vf.py:445-453) calls `rv.readings()` directly, not `rv.split()`, and `test_evaluate_arrays_uses_each_matrix_and_the_same_resamples` (test_regrade_vf.py:340-342) compares `rec[v]` to `rv.split()`.
    Concrete failure scenario: Mutating `regrade_vf.py:211` from `"SE": r["SE"]` to `"SE": se["B"]` or `regrade_vf.py:213` from `readings(B, F, M_full, r["SE"], se)` to `readings(B, F, M_full, se["B"], se)` (or swapping `B` and `F` in that call) passes all 97 tests in `test_regrade_vf.py`. (By inspection of `regrade_vf.py:210-214`, the implementation itself passes the correct arguments.)

N3. [NIT] regrade_vf.py:345 — `committed = json.loads(PINS["regrade16"][0].read_text())["evaluations"]` sits outside both `try/except` blocks in `run()`.
    If `regrade16.json` cannot be read or parsed after `global_controls()` returns (e.g., TOCTOU file deletion or a test mocking `PINS["regrade16"]` mid-run), `run()` raises an unhandled `OSError`/`ValueError`/`KeyError` instead of recording a `STOP`.
    Concrete failure scenario: Deleting or corrupting `regrade16.json` between `global_controls()` (line 338) and line 345 crashes `run()` instead of populating `STOP` in `out["evaluations"]`.

N4. [NIT] regrade_vf.py:303 — `isinstance(committed.get(k), float)` rejects an integer JSON value (e.g., `1`) even if numerically valid.
    Using `isinstance(v, (int, float)) and not isinstance(v, bool)` avoids a spurious `C-A0` STOP if a valid non-zero JSON number lacks a decimal point.
    Concrete failure scenario: Calling `evaluation_controls()` with `committed["M_full"] = 1` (exact integer) raises `Stop("C-A0: a field is missing, zero or not finite...")` even when `r0["M_full"] == 1.0`. (All six fields in `regrade16.json` are non-integer floats.)

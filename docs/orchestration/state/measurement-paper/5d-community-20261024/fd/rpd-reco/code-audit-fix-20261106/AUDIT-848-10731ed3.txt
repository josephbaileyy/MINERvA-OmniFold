**B1 (blocking, reproduced): the CFS refusal is not the first check, so some STOP paths write to CFS.**
- `require_output_root` runs only inside `Inputs.__init__` (`fd_rpd_reco.py:261`).
- Three refusals are raised before it:
  - THREADS and NICE, in `main` (`:1866-1876`);
  - DRY_RUN_SCOPE (and OUTPUT_EXISTS), in `run_stage` (`:1752-1761`).
- Each falls to the handler. The handler skips the CFS check unless the guard *is* OUTPUT_LOCATION, then runs `arguments.run.mkdir(...)` and writes `<step>.STOP.json` (`:1889-1911`).
- **Probe** (module loaded, with `Path.mkdir` and `Path.open` intercepted for `/global/cfs`, and `--run /global/cfs/cdirs/probe/rpd-output`):
  - control: `STOP OUTPUT_LOCATION`, rc 4, no mkdir;
  - with `OMP_NUM_THREADS=4`: mkdir of the CFS run directory, then `open(.../pins.STOP.json, "x")`;
  - with `d1 --dry-run`: mkdir, then `open(.../d1.STOP.json, "x")`.
- REPORT.md says the guard "rejects CFS before mkdir, including before a STOP receipt could be written there." That is false for these paths.
- `test_output_location_before_any_write` covers only the path through `Inputs`.
- **Requirement:**
  - call `require_output_root(arguments.run)` before anything else in `main`, and again in the handler before any mkdir;
  - add a test where a THREADS-refused (or dry-run-scope-refused) CFS run makes no mkdir and no write;
  - add a REQUIRED mutant for it.
- It takes two operator errors at once, but "nothing written to CFS" is a hard rule, and the PR claims this exact coverage.

**B2 (decision, measured on the real platform): the price route ends in a STOP, and no code path lets a director-priced run go on.**
- **The estimate.** `runtime_estimate` (`:1421-1457`) prices draws = 200 × (mc + 21 × (mc + data)).
  - With the declaration's 32.8M MC rows and 4,091,707 data rows, that is 1.615×10¹¹ draws. Background rows would add more.
  - On Perlmutter login26 (`/usr/bin/python3`, numpy 1.17.3, OMP=1, nice 19), the minimum of 5 timings is 31.3 ns per draw. My Mac with numpy 1.26 gives 31.7 ns.
  - So the Poisson-only time is ≈ 5,060 s, and the ×10 planning figure is ≈ 14 h, against 7,200 s.
  - The figure stays under 2 h only below ~4.5 ns per draw.
  - So `needs_director_price` is True, and `d2-predict` refuses PRICE_REVIEW (`:1766-1771`).
- **No priced route.** Binding 1 ruling 3 then sends the run to a compute node, priced to the director. The code has no input that admits that price:
  - PRICE_REVIEW reads only the estimate;
  - WALL_CLOCK hard-codes 7,200 s per invocation (`:1088-1091`, `:1179-1183`).
  - c0 runs 21 full aggregate passes in one invocation. Its Poisson draws alone are ≈ 1.3 h at 31 ns, before the per-axis, per-variant bincounts.
- **Consequence.** As the code stands, step two can produce pins and p0 and then STOP. Readings need a code amendment and re-audit.
- **The director's options:**
  - (a) Bind a director-priced budget now: for example `--priced-wall-seconds N`, recorded in each record, which replaces both 7,200 s checks and lifts PRICE_REVIEW only when it is given. Test it both ways and give it a REQUIRED mutant.
  - (b) Accept that step two stops at the p0 estimate, and bind the amendment afterwards.
- The code fails closed, so this is not a correctness defect.

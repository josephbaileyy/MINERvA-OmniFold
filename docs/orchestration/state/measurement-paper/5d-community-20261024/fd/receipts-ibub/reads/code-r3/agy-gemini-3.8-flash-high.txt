## 2. Numbered Findings and Concrete Fixes

### Finding 1: Premature write of `IBUB-DONE` with `"rc": 0` before verdict check
- **Classification:** MINOR
- **File & Line:** [`2d-unfolding/ibub/jobs/ibub_job.sbatch:125-130`](file:///private/tmp/claude-501/-Users-josephbailey-local-research-MINERvA-OmniFold/a4ec4b9a-c277-4847-8576-4e2ef26708b1/scratchpad/agy-code-r3/tree/2d-unfolding/ibub/jobs/ibub_job.sbatch#L125-L130)
- **Description:** Line 125 executes `done_json toys 0 > /dev/null` solely to query `toy_pass_markers` and `porcelain_after` via Python at lines 126–127. If the batch job is abruptly terminated by Slurm (e.g. wall clock expiry or OOM) immediately following line 125, `$N/IBUB-DONE` will persist containing `"stage": "toys", "rc": 0`, giving a false indication of success prior to the verification at line 128.
- **Fix:** Do not write `IBUB-DONE` with a speculative `0`. Instead, compute `pass` and `na` directly in shell or write to a staging file (e.g. `$N/tmp-done.json`), evaluate `ok`, and call `done_json toys $rc` exactly once:
  ```bash
  pass=$(ls "$U"/toy_*.done 2>/dev/null | xargs -r grep -l '"verdict": "PASS"' | wc -l)
  na=$(git -C "$C" status --porcelain --ignored | awk 'NF && index($0, "__pycache__") == 0 { c++ } END { print c + 0 }')
  ok=1; [ "$pass" -eq 600 ] || ok=0; [ "$na" -eq 0 ] || ok=0; [ "$(echo $TOY_RCS | tr -d ' 0')" = "" ] || ok=0
  if [ "$ok" -eq 1 ]; then done_json toys 0; say "end PASS"; exit 0; fi
  done_json toys 1; say "end: not every toy passed (pass markers $pass, lane rcs$TOY_RCS, porcelain $na)"; exit 1
  ```

### Finding 2: `srun` step job-name prefix uses hyphen (`ibub-`) instead of underscore (`ibub_`)
- **Classification:** MINOR
- **File & Line:** [`2d-unfolding/ibub/jobs/ibub_job.sbatch:70`](file:///private/tmp/claude-501/-Users-josephbailey-local-research-MINERvA-OmniFold/a4ec4b9a-c277-4847-8576-4e2ef26708b1/scratchpad/agy-code-r3/tree/2d-unfolding/ibub/jobs/ibub_job.sbatch#L70)
- **Description:** Line 70 sets `--job-name="ibub-$tag"`. The standing rule mandates the prefix `ibub_`. While the batch allocation itself is named `ibub_run` and `sacct -X` ignores steps, any step-level inspection or step-aware sacct query would fail to associate these steps with `PREFIXES=ibub_,...` because of the hyphen.
- **Fix:** Replace `--job-name="ibub-$tag"` with `--job-name="ibub_$tag"`.

### Finding 3: Fragile `acpu` regex in Slurm allocation check
- **Classification:** MINOR
- **File & Line:** [`2d-unfolding/ibub/jobs/ibub_job.sbatch:52`](file:///private/tmp/claude-501/-Users-josephbailey-local-research-MINERvA-OmniFold/a4ec4b9a-c277-4847-8576-4e2ef26708b1/scratchpad/agy-code-r3/tree/2d-unfolding/ibub/jobs/ibub_job.sbatch#L52)
- **Description:** Line 52 extracts CPU allocation using `AllocTRES=cpu=\([0-9][0-9]*\)`, assuming `cpu=` immediately follows `AllocTRES=`. In contrast, line 51 uses `AllocTRES=[^ ]*mem=\([0-9][0-9]*\)M`. If Slurm serializes TRES with any prefix ahead of `cpu` (such as `billing=` or custom TRES), line 52 will yield an empty string and refuse with exit code 2.
- **Fix:** Change line 52 to match line 51's delimiter handling:
  ```bash
  acpu=$(scontrol show job "$SLURM_JOB_ID" | sed -n 's/.*AllocTRES=[^ ]*cpu=\([0-9][0-9]*\).*/\1/p' | head -1)
  ```

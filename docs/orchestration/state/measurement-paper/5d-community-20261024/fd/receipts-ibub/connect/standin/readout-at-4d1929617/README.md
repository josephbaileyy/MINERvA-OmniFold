# The Docker stand-in of connect O, the readout, at 4d1929617 (2026-11-24, a draft)

**By** `director-helper-3`. The driver is `../standin_readout.sh`, and the image is `../Dockerfile.txt`, the same as
connect R's stand-in. The connect is the real `ibub_readout_connect.sh`, generated by `gen_readout_connect.py` with
M = JOB_M = `4d19296170d061ac1b9c810052e53b6e8e5cb4a5`. A depth-1 clone then holds the job's commit. The readout
package's final M is generated again, and this stand-in is run again there.

**What is stubbed.** The stubs are sacct (the fence rows and the job's row from the variant), git clone's URL (a
depth-1 bare repo of the commit), the MAT pin check (PY310), and the shared checkout's `setup_salloc_env.sh`. That
setup script puts a stub `python` first on PATH. The stub answers the MAT preflight and stands in for
`ibub_readout.py`: it writes a tune's two products and prints the verdict line that main() prints, with main()'s rc.
The real readout needs ROOT and MAT, and `test_ibub_readout.py` tests it. This stand-in tests the connect around it.
The job's records are fake bytes at the real paths of `$N`.

**Three container-only stubs, disclosed:** the login node has each of these, and COV2D's readouts used all three.
1. `docker run --shm-size=4g`. Docker's /dev/shm is 64 MB, too small for the clone (385 MB): the first run STOPped
   at `clone` with "No space left on device".
2. A `taskset` stub that drops `-c 8-11`. The container has fewer CPUs, and taskset refused the affinity.
3. A `/usr/bin/time` stub. The connect calls it by path, and the slim image has no `time`. The first fix put the stub
   on PATH, and rc 127 showed that it has to be at the path.

## MEDIUM

### M1. 5A's S_ref16 is projected by a different rule from C_PL,16, so the two sensitivities beside each other are not like-for-like.

**Where:** T:389 and T:394. The test restates the same rule at t:527-529 and t:534, so it cannot disagree.

- **g_X,R:** the tool averages the 2D relative offset g_X linearly over the footprint, `om @ g_X`. This is the
  linear projection of a per-bin relative offset onto a cell integral, under 5A's assumption.
- **S_ref16:** the tool averages the double ratio r_X itself over the footprint, `r_X,R = om @ r_X`, and only then
  forms `e_X (r_X,R / r_A,R − 1)`.
- **The 2D DESIGN** (`2d-closeout/playlist-term/DESIGN.md:69`) defines b_X = e_X (r_X/r_A − 1) ∘ x per 2D cell. The
  footprint average consistent with g is `e_X · om @ (r_X/r_A − 1)`.
- **The difference is first order, not second.** r_X = m(1 + g_X) and m (data over MC) varies across 2D bins. So the
  tool's ratio-of-averages re-weights the footprint by m, with weights om∘m instead of om.

**Probe P-A** (`$N/probes.log`), on the test's own fixture:
- Per-cell |tool − linear| / |linear| of b_PB: median 0.15, max 7.3.
- Per-cell σ(S_ref16), tool over linear: 0.80 to 1.50, and 0.92 to 1.66 with a 2D-like 7 % p_∥ step in m.
- The mutant that uses the linear rule is KILLED only because the test hand-codes the tool's rule.

**Scenario.** The real readout prints `sigma_rel.S_ref16` beside `C_PL16` as "S-ref projected". A reader then compares
two projections that differ by tens of percent per cell for a reason unrelated to the reference choice.

### M2. The period readout writes a forbidden form X/f − 1 for a product integral the guard does not hold.

**Where:** T:383 and T:408. The guard is built at T:464.

- For the central variant, `weight_outside_2d_support[R] = (tot − sup)/tot = 1 − X_sup,R / f_R`.
- X_sup,R is the central value's integral over the part of R's footprint inside the 2D support.
- That is |X/f − 1| for a product integral X. LeakGuard's docstring forbids exactly that form "for any such X". The
  guard is passed only f and U@prior, so it cannot see it.
- The quantity also carries the blinded result's sub-cell (p_T, p_∥) distribution.

**Probe P-C:**
- The written vector equals 1 − X_sup/f to 2e-16.
- The tool's guard counts 0 offending numbers.
- The same guard with X_sup added counts **24**.
- Mutant "planted supported-footprint share of f (1 − outside)" SURVIVES (`$N/review_mutants.log`).

This may be acceptable, since it is a shape fraction and not f. But nothing in the governing records sanctions it,
and it should be the director's call, not an untested omission.

**The comment at T:462-463 is correct as far as it goes:**
- U@xc equals f to 1e-12 (P1). Its omitted forms are about 1, about 1e-16, or below the 1e-30 floor.
- Adding U@xc would put 1 in the table and refuse every "1" in a string, for example "R01" or "1A-1F".
- So the exclusion itself is sound. The gap is the *partial* integrals.

### M4. Three listed controls cannot fire on any input. C4 and P4 are algebraic identities, so `controls_passed` overstates what was checked.

**C4 (T:325-333).**
- b~ is the w-weighted mean, so Σ w (r − b~) = 0. Then mean_w χ²_truth = mean_w χ²_b~ + b~ᵀM⁻¹b~ exactly.
- Probe P-D: over 2000 random (r, w, M) sets, the worst normalized gap is 1.4e-14, against a 1e-9 refusal.
- It guards only a code change.

**P4 (T:388-398).**
- om is shared by all three periods. So Σ e_X g_X,R = om @ (Σ e_X g_X), which is ≤ 1e-12 once P0 passes.
- With k > 0 and e > 0, k Σ e g gᵀ is PSD of rank ≤ 2 by construction, because g_C is a combination of g_A and g_B.
- Probe P-E: over 500 random footprints, the worst |Σ e g_R| is 7e-18, the worst rank is 2 and the worst min/max
  eigenvalue is −4e-16. It never fires.
- Its only test (t:577-587) bypasses P0 by calling `period_variant` on hand-broken inputs.

**Effect.** Both appear in `controls_passed` (T:350 and T:466) beside controls that test inputs. The 2D DESIGN §4
check 3 labels its analogous symmetry check "guards only against a code change". Here no such label exists.

### M5. 3a's in-span fraction has no stated reference, and its value depends on the coordinates.

**Where:** T:199-203, labelled at T:218-221.

- C_resp has rank 4, from four rank-1 species. So an isotropic random d has an expected in-span fraction of 4/16 =
  0.25. Probe P-F measured 0.249, with a 16–84 % range of 0.10 to 0.40.
- The label explains only what 1 means. A real value of, say, 0.4 cannot be read without the 0.25 chance level
  beside it.
- The Euclidean projector depends on units. For one d in probe P-F, the fraction is 0.24 in relative units and 0.99
  in absolute units (the fixture's f spans 6.7e5).
- The label does say "relative units", which is correct but is the only safeguard.

**Minor:** d is relative to rrzero (z) while the projector is built in f-relative units. That is an O(z/f − 1) mismatch.

## LOW

### L1. 4C mixes two percentile definitions between the weighted and unweighted columns.

**Where:** T:251 and T:259.

- Weighted percentiles use the inverted ECDF.
- Unweighted percentiles use `np.percentile`'s default, linear interpolation.
- At equal weights the two differ. Probe P-B, on χ²₁₆ draws of A7's sizes: up to 0.14 at the 95th percentile and
  0.08 at the 84th.
- Each test restates its own branch (t:291 and t:421-422), so neither checks that they agree.

  reader to compare.

### L2. 3a's `curvature_ratio` is not MP-1's G3 form that build_cresp prints for C_resp.

**Where:** T:204 against `build_cresp.py` `curvature_ratio`.

- The tool uses relative-unit norms ||s+ + s−|| / ||s+ − s−||.
- build_cresp uses absolute norms ||f+ + f− − 2f0|| / ||f+ − f−||.
- Probe P-G, on the same three products: 0.17 against 0.23, 0.25 against 0.29, and 0.24 against 0.10.
- Labelled only "descriptive". Set beside C_resp's per-species curvatures, the two are not comparable.
- No test checks this field (H1).

### L3. 4C's "no p value, no tail fraction" test (ruling 4) checks key names only.

**Where:** t:432-434.

- The test forbids only the key "p" and keys containing "share", "tail" or "above".

### L4. Footprint robustness.

- `footprint` (T:365-384) does not check that the fine-cell weights x_f·vol_f are non-negative. A negative fine value
  in the central or prior array would give negative om entries without refusal.
- The tool never checks that the fine grid's (p_T, p_∥) edges equal the 2D grid, or that the 2D cells use the
  `ipt*16 + ipz` encoding.
  - Both hold at present: `s5p_stage1_inspect.FINE` equals `common.py` PT_A/PZ_A, and `cell_ipt_ipz` is `// NPZ`.
  - But the encoding is assumed at T:370.
- C1 has no test for a repeated pseudo_seed. It can occur through two filenames ending in the same `_s<seed>`.

### L5. The shared `not_citable_for` reads against 4C's own content.

**Where:** T:85-87.

- Every readout, the 4C chi2 readout included, carries NOT CITABLE FOR "a coverage, calibration or
  chi2-distribution result".
- The 4C readout *is* a set of χ² distribution percentiles.
- The intent, presumably "the χ² distribution under the full model", is not what it says.
- Addendum §5.3's "a validated size" is not stated for 5A, though "cannot fail" partly covers it.

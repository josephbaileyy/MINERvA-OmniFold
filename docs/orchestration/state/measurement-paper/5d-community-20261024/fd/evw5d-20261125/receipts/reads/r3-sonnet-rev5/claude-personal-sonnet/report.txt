## Findings (all NON-BLOCKING)

1. **`accepted()` can raise instead of returning False.**
   - `evw5d.py:536-540` calls `canonical()` with `allow_nan=False` on `finding_sizes`, and `:533` calls `.get("copy_digest")` on `reads[k]` without checking it is a dict.
   - A malformed or NaN-bearing `run.json` therefore gives a traceback, not `False`.
   - It still fails closed: the Python exits non-zero, the HPSS script's `acc` is empty and it bails, and the launcher's `accepted rc` is non-zero.
   - Fix: wrap the final return in `try/except (ValueError, TypeError, AttributeError, KeyError)` and return `False`.

2. **The production sub-conditions of `accepted()` are not tested one at a time.**
   - These are `code_pin`, `main_pin`, `ess_digest`, the `reads[k].copy_digest` set and `--fixture` not in `argv` (`evw5d.py:530-535`).
   - The only positive test forges all of them together (`test_evw5d.py:1247-1265`).
   - The only negative is the fixture bundle, which fails on several at once.
   - Only `ACCEPTED_PRODUCTION` mutates the whole block, so a mutant dropping any single clause would survive.
   - The code is correct on reading, and the writer already refuses wrong digests before running.
   - Fix: forge a production-shaped bundle with one field wrong, once per field.

3. **No test runs the shell tail of the job or the connect, post and HPSS scripts.**
   - The job fixture refuses before the setup is sourced (`test_evw5d.py:943-1025`), so `srun` and the DONE write never run (`sbatch_evw5d.sh:60-68`).
   - By reading, the `srun` argv matches the `argparse` options (`evw5d.py:759-765`).
   - A mistake here fails closed and wastes the slot. It cannot publish a wrong product.

4. **A test depends on test order.**
   - `test_evw5d.py:1296-1297` needs `failf-pristine`, which only `test_fail_on_f` creates (`:288`).
   - Running with `-k`, or in a different order, fails it spuriously.
   - The mutation harness runs the whole suite, so it is unaffected.

5. **The checker Python puts the current directory ahead of the standard library.**
   - `python3 -B -c` does this in `evw5d_launch.sh:43` and `evw5d_hpss.sh:45`. The scripts insert the checker directory first, but `''` still precedes stdlib and numpy.
   - A stray `json.py` or `numpy/` in the working directory could shadow them.
   - Fix: use `python3 -I -B -c`. The scripts' own `sys.path.insert` still works under `-I`.

## Answers to the questions

1. **Key and alignment.**
   - `entry = flatnonzero(pass_truth)` (`evw5d.py:185`) is the index of each row in `MCgen`.
   - The driver filters with `MCgen[pass_truth]` and `w_pull[pass_truth]` in order (`omnifold_nn_core.py:210-215`), and the push is evaluated on that slice (`:266`).
   - The central pair has no permute, bootstrap or jitter. `--pairs=-:-` gives `j is None` and passes the inputs through (`s5p_numerics.py:181-182`). `build_data` and `unf_inputs` copy the references (`s5n_pseudo.py:197-199`, `s5e_trace.py:438-442`).
   - `main` calls `bootstrap_replica` only when `b is not None`, and there is no permute option.
   - C-KEY (`evw5d.py:257-270`) proves the received arrays are bit-equal to an independent `allow_pickle=False` read of the same sha-pinned bytes. That rules out any reorder or filter.
   - The pairing of `wpush[i]` with `entry[i]` rests on the code above, plus the fact that the captured object is the very array the driver histograms (`s5c_unfold.py:138`). C-KEY itself checks only the push length.
   - A permutation inside one fine cell would not change the bit-for-bit re-histogram, but no path produces one.

2. **Weights.**
   - `w_unfolded = wpush * d["w_truth"][m]` (`evw5d.py:194`) is the same expression as `s5c_unfold.py:138`.
   - `loops[0][1]` is the second element, `w_push` (`omnifold_nn_core.py:268`; `capture_unfold`, `evw5d.py:575`).
   - `MCgen` is float32 (`nn_dump_inputs.py:84`), and truth columns are saved at that precision. `w_truth` is float64 (`unfold_nd_omnifold_unbinned.py:466`).
   - LightGBM returns float64, and any widening is exact. `pass_truth` is bool (`:465`), and the writer refuses anything else.

3. **Gates.**
   - C-BIND compares each product parsed from the bytes it hashed. Members, `xsec_flat` and `shape` are compared bit for bit with dtype, and the meta is compared type-strictly minus `PER_RUN`.
   - C-F's row formula and operand order match ESS's (B). Both the result and the row sums are compared with the data product's f.
   - On the real run, the meta compare can only be stricter than ESS's `==` on types, and both metas come from the same code.
   - NaN in the reference meta cannot occur. It would have shown up as a differing key in ESS's equality.
   - `canonical()` would raise on NaN (`evw5d.py:246`), but that cannot fire for the same reason.

4. **Read-back.**
   - C-FILE, C-SELF and C-FLOW run on `read_npz` output, which hashes and parses the same bytes (`evw5d.py:138-147`).
   - Inputs are checked against the independent read. The builder-made constants are re-derived (`good`, `xsec_flat`, 1e4, volumes), and the saved map, meta pins, key text, axes and formula are checked against fixed constants.
   - Every product is covered: `run.json` and the marker through `accepted()`, `product/` through C-BIND, and `constants.json` through `check_constants_json`.
   - Every constant a user needs is present: edges, flux per pT bin, POT, N, 1e4, `denom_nd`, `ofin`, completeness, `good`, volume, map and `xsec_flat`.
   - `FORMULA_TEXT` matches `xsec_nd.py:77-83`. The unit label is correct (m⁻²/POT).

## Scope — NARROWED, and narrowed to what the verifier actually asked for

**HELD: `nd-unfolding/`.** The verifier executes those modules and its verdict cites `path + blob
sha256` per module plus the launcher's adopt segment digest. If those bytes move mid-run its verdict
is about different code than it ran.

**ALSO HELD, one file and not the directory: `docs/orchestration/state/ben106-stamp-verify-active-56695424.json`.**
Added 2026-08-21 on the verifier's correction, after I published a scope that was incomplete by
exactly this path. It is **a gate operand, not documentation**:
`mii_adopt_unified_5d_stamped.assert_pinned_writer_is_intact` opens it every run
(`BINDING_RECEIPT`, set at `:154`), reads `rec["implementation_sha256"]`, and refuses if it does not
equal the on-disk sha256 of `adopt_unified_5d.py`. Verified here rather than taken on trust: both
sides currently read `e1260e8dec2d39cb4653…`, and the module also carries a `launcher_sha256`.
The verifier's whole subject is a wrapper whose safety argument is that it *runs the bytes the
receipt names*, so if this file moves mid-run every subsequent arm either refuses for a reason
unrelated to what is under test, or — worse — passes against a **re-pinned** digest, certifying a
re-binding nobody measured. **I missed it because I scoped the hold by what the verdict CITES rather
than by what the executing code READS.** Those are different sets and the second is the one that can
invalidate a run.

**NOT HELD: the rest of `docs/orchestration/`, `docs/`, `docs/analysis-note/`, anything generated.** My first

## As first stated it was UNSATISFIABLE, and that is a structural point rather than a slip

`control_plane_lint.py` is **pre-commit check 10** and fails closed on a stale
`docs/orchestration/control-plane/source-record-inventory.tsv`. That inventory is regenerated by any
edit to `docs/OPEN_ITEMS.md`, and it lives under `docs/orchestration/`. So "do not move
`docs/orchestration/`" plus "the hook requires the regenerated inventory" means **nobody could commit
any `OPEN_ITEMS.md` edit at all** except by breaking the hold or bypassing the hook. Two rules each
correct in its own scope, each safe only under a precondition the other removes — the composition
defect this campaign keeps filing, and this time I authored one of the halves.

Measured by the OI-148 lane, which hit exactly that failure once, and confirmed here: the hook runs
12 checks and `control_plane_lint.py` is number 10.

## Standing rule this establishes

A hold that binds another lane must be **committed with its scope and its expiry before it binds
anyone**, and its scope must **exclude generated output** or it forbids editing the live records that
generate it. Filed as the lesson, not as a rule I am imposing: the OI-148 lane proposed both clauses
and I am recording them because it was right.
